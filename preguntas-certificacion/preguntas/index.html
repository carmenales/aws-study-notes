    Mantener IP de origen tras un LB

    A company is planning to deploy an application on AWS behind an Elastic Load Balancer. The application uses an HTTP/HTTPS listener and must access the client IP addresses. Which load-balancing solution meets these requirements?

    • A. Use an Application Load Balancer and the X-Forwarded-For headers.
    • B. Use a Network Load Balancer (NLB). Enable proxy protocol support on the NLB and the target application.
    • C. Use an Application Load Balancer. Register the targets by the instance ID.
    • D. Use a Network Load Balancer and the X-Forwarded-For headers.
    Ver Respuesta, Análisis e Información Relevante

    Respuesta: A (Probabilidad: 80%)

    Análisis: La A es algo que se hace por ejemplo con docker cuando hay cambio de red. La B y la D es a nivel TCP, no HTTP. La C no suena mal pero creo recordar que al registrar los targets se puede hacer por security group y era más lógico.

    DynamoDB con GSI para futuras consultas

    A company has an ecommerce platform. A developer is designing an Amazon DynamoDB table to store customer order data for the platform. The table uses the order ID as the partition key. The developer needs to modify the table to get all order IDs that are associated with a given customer email address in a single query. The solution must give the developer the ability to query order IDs by other item attributes in the future. Which solution will meet these requirements?

    • A. Configure the partition key to use the customer email address as the sort key.
    • B. Update the table to use the customer email address as the partition key.
    • C. Create a local secondary index (LSI) with the customer email address as the sort key.
    • D. Create a global secondary index (GSI) with the customer email address as the partition key.
    Ver Respuesta, Análisis e Información Relevante

    Respuesta: D (Probabilidad: 70%)

    Análisis: El hecho de que los datos estén particionados por orderID no facilita la query que tiene que consultar todos los orderIDs de un customer concreto, porque tendrías que ir a muchas particiones a pillar trocitos. Además piden que the solution must give the developer the ability to query order IDs by other item attributes in the future, con lo cual todavía peor. La A me suena rara. La B mejoraría las queries por customer y luego podría quizá ordenar por pedido. La D no resuelve el problema de buscar por otros campos no indexados, pero sí es verdad que creando otros GSI resolvemos todo el escenario.

    Evitar invocaciones cruzadas de S3 y Lambda

After a recent production deployment, the development team observed that the development S3 buckets invoked the production environment Lambda functions. The team must follow security best practices. Which solution will meet these requirements?

    • A. Update the Lambda execution role for the production Lambda function to add a policy that allows the execution role to read from only the production environment S3 bucket.
    • B. Move the development and production environments into separate AWS accounts. Add a resource policy to each Lambda function to allow only S3 buckets that are within the same account to invoke the function.
    • C. Add a resource policy to the production Lambda function to allow only the production environment S3 bucket to invoke the function.
    • D. Move the development and production environments into separate AWS accounts. Update the Lambda execution role for each function to add a policy that allows the execution role to read from the S3 bucket that is within the same account.
    Ver Respuesta, Análisis e Información Relevante

    Respuesta: C (Probabilidad: 60%)

    Análisis: Usar Lambda functions con Amazon S3 trigger para set up de múltiples entornos con un S3 Bucket con una sola cuenta de AWS. El problema es que están usando ficheros del entorno de desarrollo en el de producción al usar esas lambda functions. Quieren buenas prácticas. La C tiene pinta que es cierta.

    STS y CloudFront sin credenciales hardcoded

    A social media application uses the AWS SDK for JavaScript on the frontend to get user credentials from AWS Security Token Service (AWS STS). The application stores its assets in an Amazon S3 bucket. The application serves its content by using an Amazon CloudFront distribution with the origin set to the S3 bucket. The credentials for the role that the application assumes to make the SDK calls are stored in plaintext in a JSON file within the application code. The developer needs to implement a solution that will allow the application to get user credentials without having any credentials hardcoded in the application code. Which solution will meet these requirements?

    • A. Add a Lambda@Edge function to the distribution. Invoke the function on viewer request. Add permissions to the function's execution role to allow the function to access AWS STS. Move all SDK calls from the frontend into the function.
    • B. Add a CloudFront function to the distribution. Invoke the function on viewer request. Add permissions to the function's execution role to allow the function to access AWS STS. Move all SDK calls from the frontend into the function.
    • C. Add a Lambda@Edge function to the distribution. Invoke the function on viewer request. Move the credentials from the JSON file into the function. Move all SDK calls from the frontend into the function.
    • D. Add a CloudFront function to the distribution. Invoke the function on viewer request. Move the credentials from the JSON file into the function. Move all SDK calls from the frontend into the function.
    Ver Respuesta, Análisis e Información Relevante

    Respuesta: A (Probabilidad: 80%)

    Análisis: Los credenciales para el rol de la aplicación que usa el AWS SDK asume que hace llamadas almacenadas en texto plano en JSON dentro del código de la aplicación. Los desarrolladores necesitan obtener las credenciales de usuarios sin harcodear en el código de la aplicación. Por tanto, yo elegiría la A.

    Información Relevante: CloudFront está limitado por diseño: solo soporta un subconjunto de JavaScript y no tiene acceso a red ni puede hacer llamadas a otros servicios de AWS como STS. Lambda@Edge sí puede ejecutar código y acceder a otros servicios de AWS.

    Lambda y RDS: mover la conexión al global space

    A developer has implemented an AWS Lambda function that inserts new customers into an Amazon RDS database. The function is expected to run hundreds of times each hour. The function and RDS database are in the same VPC. The function is configured to use 512 MB of RAM and is based on the following pseudo code. After successfully testing the function multiple times, the developer notices that the execution time is longer than expected. What should the developer do to improve performance?

    • A. Increase the reserved concurrency of the Lambda function.
    • B. Increase the size of the RDS database to facilitate an increased number of database connections each hour.
    • C. Move the database connection and close statement out of the handler. Place the connection in the global space.
    • D. Replace Amazon RDS with Amazon DynamoDB to implement control over the number of writes per second.
    Ver Respuesta, Análisis e Información Relevante

    Respuesta: C (Probabilidad: 80%)

    Análisis: El concepto clave es el ciclo de vida del entorno de ejecución de Lambda. Si el pseudocódigo abre y cierra la conexión dentro del handler, cada invocación repite un proceso costoso. Al mover la conexión al global space, Lambda la crea una vez por entorno de ejecución y la reutiliza en warm starts, evitando el coste repetido.

    Información Relevante: https://docs.aws.amazon.com/lambda/latest/dg/best-practices.html

    Elastic Beanstalk sin downtime y con cambio de plataforma

    A company has a front-end application that runs on four Amazon EC2 instances behind an Elastic Load Balancer (ELB) in a production environment that is provisioned by AWS Elastic Beanstalk. A developer needs to deploy and test new application code while updating the Elastic Beanstalk platform from the current version to a newer version of Node.js. The solution must result in zero downtime for the application. Which solution meets these requirements?

    • A. Clone the production environment to a different platform version. Deploy the new application code, and test it. Swap the environment URLs upon verification.
    • B. Deploy the new application code in an all-at-once deployment to the existing EC2 instances. Test the code. Redeploy the previous code if verification fails.
    • C. Perform an immutable update to deploy the new application code to new EC2 instances. Serve traffic to the new instances after they pass health checks.
    • D. Use a rolling deployment for the new application code. Apply the code to a subset of EC2 instances until the tests pass. Redeploy the previous code if the tests fail.
    Ver Respuesta, Análisis e Información Relevante

    Respuesta: C

    Análisis: La C por lo que he leído en la documentación es la opción más segura en el entorno de producción porque asegura rollback si falla. La D parece un poco liosa.

    Información Relevante: Los métodos Rolling y Rolling with additional batch actúan sobre las instancias existentes y no admiten cambios de versión de plataforma; solo Immutable y All at once pueden aplicar una actualización de plataforma creando instancias nuevas.

    Elastic Beanstalk: actualización de aplicación

    • B. Package the application code into a .tar file. Use the AWS Management Console to create a new application version from the .tar file. Update the environment by using the AWS CLI.
    • C. Package the application code into a .tar file. Use the AWS Management Console to upload the .tar file and deploy the packaged application.
    • D. Package the application code into a .zip file. Use the AWS CLI to create a new application version from the .zip file and to update the environment.
    • E. Package the application code into a .zip file. Use the AWS Management Console to create a new application version from the .zip file. Rebuild the environment by using the AWS CLI.
    Ver Respuesta, Análisis e Información Relevante

    Respuesta: A y D

    Análisis: Elastic Beanstalk trabaja siempre con paquetes .zip (o .war para Java), nunca con .tar; y para aplicar una nueva versión, la acción correcta siempre es update el entorno, nunca rebuild.

    Información Relevante: La opción A es correcta y la D también es correcta. B y C fallan por usar .tar, y E falla por usar rebuild.

    Información Relevante: El requisito clave es mantener una sola copia del documento original en S3 y poder servir dos versiones según quién lo solicite: la versión completa con PII para usuarios internos autorizados y la versión redactada sin PII para terceros.

    S3 Object Lambda permite añadir código propio a las solicitudes GET estándar de S3 para procesar y modificar los datos devueltos a la aplicación, sin crear ni almacenar copias adicionales del objeto.

    El funcionamiento es el siguiente:

    • Se crea un S3 Access Point normal sobre el bucket.
    • Sobre ese access point se crea un S3 Object Lambda Access Point asociado a la función Lambda removePii.
    • Cuando una solicitud GET llega a través del Object Lambda Access Point, S3 invoca automáticamente la función Lambda, que recibe el objeto original, elimina la PII y devuelve la versión transformada al solicitante.
    • Cuando se accede al objeto mediante el endpoint estándar de S3, sin pasar por el Object Lambda Access Point, se obtiene el documento original sin transformación.

    Esto resuelve el requisito de almacenar un único objeto en S3 y utilizar dos rutas de acceso distintas: el endpoint normal devuelve el documento completo y el S3 Object Lambda Access Point devuelve el documento redactado.
